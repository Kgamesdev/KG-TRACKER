# AUDITORÍA TÉCNICA — KG TRACKER

## 1. Resumen ejecutivo

Se ha realizado una auditoría técnica integral sobre la base de código del proyecto **KG Tracker** (v0.1.21/v0.1.23-stable). El proyecto es una aplicación de escritorio nativa para Windows construida con **Python 3.14+** y **PySide6 (Qt 6)** cuyo propósito es agregar, filtrar y notificar ofertas de videojuegos gratuitos para PC.

**Conclusiones clave:**
- **Estado general:** La aplicación posee una interfaz bien pulida a nivel de experiencia visual (temas QSS, notificaciones de sistema, bandeja de entrada), pero presenta vulnerabilidades estructurales graves en concurrencia, persistencia de datos y arquitectura de clases.
- **Riesgo crítico (P0):** Se han identificado fallos de **concurrencia sin protección por cerrojos (thread safety)** en los servicios de caché, **vulnerabilidades de inyección de comandos** en el motor de audio por ejecuciones inseguras de PowerShell, **escrituras no atómicas en disco** que arriesgan la pérdida total del historial de juegos reclamados (`reclamados.json`) y **código duplicado/corrupto** con fragmentos huérfanos.
- **Deuda técnica significativa (P1/P2):** La ventana principal fragmenta su lógica mediante un anti-patrón de *monkey-patching* masivo (`instalar_metodos(cls)`), eliminando la inferencia de tipos y autocompletado en IDEs. Además, coexisten dependencias pesadas no utilizadas (`numpy`, `@google/genai`) y un cliente `requests.Session` compartido indebidamente entre hilos secundarios.

## 2. Arquitectura detectada

```text
               +----------------------------------+
               |        main.py (Entry)           |
               +----------------------------------+
                                |
               +----------------------------------+
               |     ui/main_window.py (Qt)       |
               +----------------------------------+
                 /       |        |        |    \
   (Monkey-patching via instalar_metodos)       
   main_window_ui.py  _games.py  _history.py ...  
                 \       |        |        |    /
         +---------------+--------+--------+-------+
         |                                         |
+------------------+                    +--------------------+
|  core/storage.py |                    | core/translator.py |
| (Persistencia)   |                    | (Async QThread x3) |
+------------------+                    +--------------------+
         |                                         |
+----------------------+                +--------------------+
| core/steam_enricher  |                | core/image_loader  |
| (QThreadPool Steam)  |                | (QThreadPool RAM/L2|
+----------------------+                +--------------------+
```

- **Patrón GUI:** Basado en PySide6 (`QMainWindow`). Se utiliza un patrón de composición dinámica no estándar donde `main_window.py` delega su implementación a 8 submódulos mediante inyección en runtime (`instalar_metodos(cls)`).
- **Concurrencia:** Modelo híbrido que combina `QThread` (Traductor), `QThreadPool` + `QRunnable` (Steam Enricher e Image Loader), y hilos de Python nativo `threading.Thread` (Audio).
- **Capa de Datos:** Archivos JSON locales (`settings.json`, `reclamados.json`, `steam_cache.json`, `translations_cache.json`, `giveaways_cache.json`).

## 3. Hallazgos críticos P0

### [P0] Condición de carrera e inestabilidad por accesos concurrentes a caché (`SteamEnricher` y `GameTranslator`)
- **Evidencia:** En `core/steam_enricher.py`:
  ```python
  class _SteamWorker(QRunnable):
      def run(self):
          datos = self.enricher._obtener_resenas_sincrono(self.titulo)

  def _obtener_resenas_sincrono(self, titulo: str) -> dict:
      # Modifica self.cache y escribe a disco sin bloqueo:
      self.cache[t_limpio.lower()] = res
      _guardar_cache(self.cache)
  ```
- **Problema:** Múltiples hilos en el `QThreadPool` global leen y mutan concurrentemente el diccionario `self.cache` de Python sin ningún cerrojo (`QMutex` o `threading.Lock`). Adicionalmente, invocan `_guardar_cache()` en paralelo, sobreescribiendo el mismo archivo temporal `.tmp` en el sistema de archivos.
- **Impacto:** Corrupción de memoria/diccionario en ejecuciones concurrentes, `PermissionError` o corrupción del archivo JSON `steam_cache.json` al renombrar archivos temporales simultáneamente.
- **Causa probable:** Suposición errónea de que las operaciones sobre diccionarios en Python son thread-safe bajo cargas I/O asíncronas.
- **Solución recomendada:** Proteger los accesos de lectura/escritura a `self.cache` y a disco con un `QMutex` o `threading.Lock`.
- **Prioridad:** P0

---

### [P0] Vulnerabilidad de inyección de comandos en `core/audio.py` mediante ejecuciones de PowerShell
- **Evidencia:** En `core/audio.py`, líneas 144-148:
  ```python
  cmd = f'(New-Object Media.SoundPlayer "{ruta_temp}").PlaySync()'
  self.proceso_audio = subprocess.Popen(
      ["powershell", "-NoProfile", "-Command", cmd],
      stdout=subprocess.DEVNULL,
      stderr=subprocess.DEVNULL
  )
  ```
- **Problema:** La ruta `ruta_temp` se interpola directamente dentro del comando en cadena formateada de PowerShell sin sanitización de caracteres de escape ni comillas.
- **Impacto:** Si la ruta del proyecto o del archivo temporal contiene caracteres especiales (como comillas dobles, comillas simples, `$`, `;` o comas), el comando de PowerShell fallará en el mejor de los casos o permitirá la ejecución de comandos no arbitrarios en el peor. Adicionalmente, crear un subproceso de PowerShell para reproducir audio WAV genera un costo de CPU y RAM completamente desproporcionado.
- **Causa probable:** Solución improvisada para evitar dependencias nativas de audio.
- **Solución recomendada:** Eliminar la invocación a PowerShell vía `subprocess`. Si se utiliza `pygame-ce` en el proyecto (ya listado en `requirements.txt` y usado en `main_window_audio.py`), unificar todo el audio bajo `pygame.mixer` o usar APIs nativas de Windows como `winsound` (`winsound.PlaySound`).
- **Prioridad:** P0

---

### [P0] Bypass del mecanismo atómico de datos en `ui/main_window_history.py` con riesgo de pérdida del historial
- **Evidencia:** Mientras que `core/storage.py` implementa `guardar_json_atomico` con copia de seguridad `.bak` y reemplazo seguro, `ui/main_window_history.py` escribe el historial de juegos directamente con el I/O por defecto de Python:
  ```python
  def _guardar_reclamados(self):
      with open(self._ruta_reclamados(), "w", encoding="utf-8") as f:
          json.dump(self.reclamados, f, ensure_ascii=False, indent=2)
  ```
- **Problema:** Si la aplicación o el sistema operativo experimentan un cierre repentino (corte de luz, crash, apagado forzado) en el milisegundo en que `open("w")` vacía el archivo `reclamados.json`, la información se pierde irremediablemente.
- **Impacto:** Pérdida total de los juegos marcados como reclamados y el contador de dinero ahorrado (`$ AHORRADO`) por parte del usuario.
- **Causa probable:** Falta de adopción del módulo centralizado `core/storage.py` durante refactorizaciones previas.
- **Solución recomendada:** Reemplazar las llamadas directas a `open()` en `ui/main_window_history.py` por `guardar_json_atomico` y `cargar_json_seguro` de `core/storage.py`.
- **Prioridad:** P0

---

### [P0] Código duplicado corrupto e instrucciones huérfanas en módulos UI
- **Evidencia:**
  1. En `ui/main_window_helpers.py`, la función `_actualizar_textos_idioma(self)` está definida dos veces consecutivas al final del archivo (líneas 130 a 180), sobreescribiéndose a sí misma.
  2. En `ui/main_window_history.py` (líneas 68-76), existen bloques descontextualizados y fragmentados dentro de la función `_cargar_reclamados`:
     ```python
     if _scroll_bar and hasattr(_scroll_bar, 'verticalScrollBar'):
         from PySide6.QtCore import QTimer
     ```
- **Problema:** Fragmentos de refactorizaciones fallidas o fusiones con errores (*merge artifacts*) que ensucian el entorno de ejecución e introducen comportamientos impredecibles.
- **Impacto:** Confusión al mantener el código, riesgo de sintaxis rota y ejecuciones accidentales de código muerto.
- **Causa probable:** Copiar y pegar fragmentos durante la división de `main_window.py`.
- **Solución recomendada:** Limpiar los archivos `ui/main_window_helpers.py` y `ui/main_window_history.py`, eliminando las definiciones duplicadas y los bloques residuales.
- **Prioridad:** P0

## 4. Hallazgos P1

### [P1] Arquitectura de monos (*Monkey-Patching*) masivo en VentanaPrincipal
- **Evidencia:** En `ui/main_window.py`:
  ```python
  instalar_metodos_tema(VentanaPrincipal)
  instalar_metodos_ui(VentanaPrincipal)
  instalar_metodos_audio(VentanaPrincipal)
  instalar_metodos_games(VentanaPrincipal)
  instalar_metodos_history(VentanaPrincipal)
  instalar_metodos_navigation(VentanaPrincipal)
  ...
  ```
- **Problema:** En lugar de utilizar patrones de diseño limpios como Mixins, Herencia, o Composición con objetos controladores/delegados, la aplicación inyecta decenas de funciones sueltas a la clase `VentanaPrincipal` mediante llamadas manuales a `instalar_metodos(cls)`.
- **Impacto:**
  - Inexistencia de comprobación estática de tipos (Mypy/Pyright inservibles).
  - Imposibilidad de autocompletado en entornos IDE (VS Code / PyCharm).
  - Dificultad extrema para rastrear dónde está definido un método o atributo de `self`.
- **Solución recomendada:** Refactorizar gradualmente los módulos `main_window_*.py` a clases de servicio o Mixins formales (`class MainWindowGamesMixin: ...`) heredadas jerárquicamente por `VentanaPrincipal`.
- **Prioridad:** P1

---

### [P1] Uso inseguro de `requests.Session` compartido entre hilos concurrentes
- **Evidencia:** En `core/steam_enricher.py`:
  ```python
  class SteamEnricher:
      def __init__(self):
          self.session = requests.Session()
      # Invocado desde hilos secundarios _SteamWorker:
      res = _consultar_steam_red(self.session, t_limpio)
  ```
- **Problema:** La clase `requests.Session()` no es thread-safe cuando múltiples hilos ejecutan peticiones HTTP simultáneamente a través de la misma instancia del pool de conexiones `urllib3`.
- **Impacto:** Posible entremezclado de respuestas HTTP, desalineación de cookies/headers, o excepciones internas `ProtocolError`/`ReadTimeout` bajo alta concurrencia.
- **Causa probable:** Intento de reutilizar conexiones TCP Keep-Alive sin considerar la concurrencia de `QThreadPool`.
- **Solución recomendada:** Crear una instancia local de `requests.Session()` dentro del método `run()` de cada `_SteamWorker` o utilizar un Thread Local storage (`threading.local()`).
- **Prioridad:** P1

---

### [P1] Web Scraping frágil basado en expresiones regulares sobre HTML crudo
- **Evidencia:** En `ui/main_window_games.py`, la función `_obtener_itch_directo()` procesa la web de Itch.io así:
  ```python
  chunks = content_html.split('data-game_id="')[1:]
  for chunk in chunks:
      title_m = re.search(r'<div class="game_title">\s*<a[^>]+href="([^"]+)"[^>]*>([^<]+)</a>', chunk)
  ```
- **Problema:** Parsear HTML estructurado mediante división de cadenas y expresiones regulares rígidas es extremadamente propenso a fallos ante cualquier cambio estético menor en el marcado de Itch.io.
- **Impacto:** Si Itch.io modifica una clase CSS o añade atributos HTML, la captura de juegos fallará silenciosamente o provocará errores de extracción.
- **Solución recomendada:** Emplear una librería de parseo HTML robusta (como `BeautifulSoup` o `selectolax`) o encapsular los scrapers con un manejo defensivo de fallos (*fallbacks*).
- **Prioridad:** P1

## 5. Hallazgos P2

### [P2] Ineficiencia de renderizado y destrucción total de widgets en UI
- **Evidencia:** En `ui/main_window_games.py`:
  ```python
  def _actualizar_vista_juegos(self):
      self._clear_layout(self.frame_lista_layout)
      # Recrea todos los componentes GameCard desde cero
      for juego in juegos:
          self.frame_lista_layout.addWidget(GameCard(self, juego, store))
  ```
- **Problema:** Cada vez que el usuario cambia un filtro de tienda o expande un acordeón, se destruyen todos los widgets gráficos existentes y se vuelven a instanciar todas las tarjetas `GameCard`.
- **Impacto:** Parpadeos gráficos, consumo elevado de CPU/GC al crear objetos Qt, y disparo redundante de solicitudes asíncronas de imágenes y reseñas de Steam para juegos que ya estaban cargados.
- **Solución recomendada:** Implementar reutilización de widgets (Object Pooling) o simplemente ocultar (`widget.hide()`) y mostrar (`widget.show()`) los widgets existentes en lugar de destruirlos.
- **Prioridad:** P2

---

### [P2] Animación continua no optimizada en `RoundedButton` (Alto consumo de CPU en reposo)
- **Evidencia:** En `ui/game_card.py`:
  ```python
  self._anim.setLoopCount(-1) # Bucle infinito
  self._anim.valueChanged.connect(lambda v: (..., self.update()))
  ```
- **Problema:** El botón de "AHORRADO" mantiene un temporizador de animación activo a 60 FPS llamando continuamente a `self.update()`, obligando a PySide6 a repintar el widget sin descanso.
- **Impacto:** Consumo constante de 3% a 8% de CPU en segundo plano estando la aplicación en reposo (*idle*), reduciendo la autonomía de la batería en ordenadores portátiles.
- **Solución recomendada:** Detener el temporizador de animación cuando la ventana pierde el foco o se minimiza a la bandeja de sistema (`changeEvent`).
- **Prioridad:** P2

---

### [P2] Falta de persistencia atómica en `giveaways_cache.json`
- **Evidencia:** En `ui/main_window_games.py`, la función `_guardar_en_cache_disco` escribe la caché de juegos directamente con `open(..., "w")`.
- **Problema:** Misma omisión que en el historial: no utiliza el guardado atómico.
- **Impacto:** Posible corrupción del archivo de caché en disco si la app se cierra bruscamente durante una búsqueda.
- **Solución recomendada:** Redirigir la escritura a `guardar_json_atomico()`.
- **Prioridad:** P2

## 6. Hallazgos P3/P4

### [P3] Inconsistencia en la gestión de Logs (`print` vs `logger.py`)
- Evidencia: La aplicación cuenta con un módulo de registro completo (`logger.py`), pero módulos clave como `ui/main_window_games.py`, `core/api.py`, `core/tray.py` y `ui/main_window_audio.py` usan `print(...)` con emoticonos.
- Impacto: Los registros de producción guardados en `logs/kgametracker_YYYY-MM-DD.log` no capturan la información crítica de red o errores de tray.
- Solución: Reemplazar los `print()` por llamadas al logger centralizado (`log_info`, `log_error`, `log_warning`).

---

### [P4] Contradicción en las licencias del proyecto
- Evidencia: `README.md` declara que el proyecto está bajo licencia **MIT** ("license-MIT-green"), pero el archivo `LICENSE` en la raíz contiene una licencia personalizada **Non-Commercial License** que prohíbe explícitamente el uso comercial.
- Impacto: Ambigüedad legal para los usuarios y contribuidores.
- Solución: Sincronizar la insignia del `README.md` con la licencia real del archivo `LICENSE`.

## 7. Seguridad

1. **Inyección de Comandos (Subprocess):** Identificada en `core/audio.py` al formatear cadenas sin escapar en PowerShell.
2. **Validación SSL y Headers:** Las peticiones HTTP a la API de GamerPower, Steam, Epic e Itch.io usan HTTPS correctamente. Sin embargo, en `_consultar_traduccion_red` (`core/translator.py`) y scrapers de `main_window_games.py`, los User-Agents imitan navegadores reales sin rotación de proxies ni verificación de firmas API.
3. **Escritura en Registro de Windows (`winreg`):** La función `habilitar_autostart()` en `core/autostart.py` interactúa adecuadamente con `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`. No requiere privilegios de Administrador (HKLM), lo cual es correcto a nivel de seguridad.

## 8. Rendimiento

- **L1 / L2 Cache de Imágenes:** La implementación de `ImageLoader` con RAM + Disco (hash SHA-256) es eficiente y evita descargas redundantes.
- **Uso de CPU en Reposo:** Elevado debido a los bucles infinitos de animación en `RoundedButton` (`_anim.setLoopCount(-1)`).
- **Consumo de Memoria:** Moderado (~100MB - 180MB RAM), aceptable para PySide6/Qt6 en Windows.

---

## 9. PySide6 / UI

- **Evitación de Micro-congelamientos:** Buen desemparejamiento de peticiones de red pesadas mediante `QThreadPool` y `QThread`.
- **Fuga de Memoria potencial en layouts:** En `_clear_layout(layout)`:
  ```python
  while layout.count():
      item = layout.takeAt(0)
      widget = item.widget()
      if widget is not None:
          widget.setParent(None)
          widget.deleteLater()
  ```
  `deleteLater()` es correcto en Qt, pero llamar a `_clear_layout` constantemente destruyendo decenas de `GameCard` recarga el recolector de basura de Python.

## 10. APIs, red y persistencia

- **Tolerancia a fallos en APIs:** El módulo `ui/main_window_games.py` implementa un excelente fallback multitienda (GamerPower -> Tiendas directas: Epic, Steam, Itch.io, GOG).
- **Persistencia atómica (Inconsistencia):**
  - `core/storage.py` contiene código de alta calidad para escritura atómica (`fsync` + `.tmp` + `.bak` + `os.replace`).
  - **Problema:** Los submódulos UI no lo importan y usan `open(..., "w")` directamente.

## 14. Deuda técnica

1. **Uso dual de motores de audio:** `ui/main_window_audio.py` usa `pygame.mixer`, mientras que `core/audio.py` usa `subprocess` con PowerShell.
2. **Duplicación de lógica de parseo de precios:** La función `_parsear_valor_juego` está duplicada o reimplementada con expresiones regulares varias veces en la interfaz y en los tests.
3. **Impresiones por consola (`print`) omnipresentes:** Dificultan la depuración en builds distribuidos sin consola (`pythonw` / PyInstaller `-w`).

## 15. Plan de acción priorizado

### Fase 1: Estabilidad Crítica y Seguridad (Inmediato - Prioridad P0)
1. **Thread Safety en Caché:** Incorporar `threading.Lock()` o `QMutex` en `SteamEnricher` (`core/steam_enricher.py`) y `GameTranslator` (`core/translator.py`) para sincronizar el acceso a los diccionarios de caché y la escritura en disco.
2. **Eliminar Subprocess PowerShell:** Eliminar la ejecución de PowerShell en `core/audio.py`. Centralizar la reproducción de audio en `pygame.mixer` (usado por `main_window_audio.py`).
3. **Persistencia Atómica Obligatoria:** Reemplazar todas las operaciones `open(..., "w")` en `ui/main_window_history.py` y `ui/main_window_games.py` por `guardar_json_atomico` de `core/storage.py`.
4. **Limpieza de Código Duplicado:** Eliminar las líneas duplicadas de `_actualizar_textos_idioma` en `ui/main_window_helpers.py` y sanear `ui/main_window_history.py`.

### Fase 2: Robustez y Calidad de Código (Corto Plazo - Prioridad P1/P2)
1. **Peticiones Thread-Safe:** Instanciar `requests.Session()` por cada worker asíncrono en lugar de compartir una sesión global entre hilos.
2. **Optimización de Renderizado UI:** Modificar `_actualizar_vista_juegos` para ocultar/mostrar tarjetas existentes en lugar de destruirlas con `_clear_layout()` en cada interacción.
3. **Pausar Animaciones en Idle:** Detener los timers de `QVariantAnimation` en `RoundedButton` cuando la ventana se minimice a la bandeja.
4. **Depurar Dependencias:** Eliminar `numpy` de `requirements.txt` y borrar `package.json`/`package-lock.json` si no se usa Node.js.

### Fase 3: Arquitectura y Mantenibilidad (Mediano Plazo - Prioridad P3/P4)
1. **Refactorizar Monkey-Patching:** Convertir `ui/main_window_*.py` en clases Mixin estandarizadas.
2. **Unificar Logging:** Reemplazar las sentencias `print()` por `log_info()`, `log_error()` de `logger.py`.
3. **Aumentar Cobertura de Tests:** Crear tests unitarios con `pytest` para la capa `core/`.

---

## 16. Conclusión

**KG Tracker** posee una base funcional sólida y una rica suite de características visuales y de integración con Windows. Sin embargo, su madurez técnica se ve mermada por fallos graves de concurrencia y persistencia no atómica que amenazan la integridad de los datos del usuario en producción. Ejecutando el **Plan de Acción Priorizado** propuesto, el proyecto alcanzará un nivel de estabilidad, seguridad y rendimiento de categoría profesional.
